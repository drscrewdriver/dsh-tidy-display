# dsh-tidy-display

[简体中文](README.md) | [English](README.en.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Italiano](README.it.md) | [Русский](README.ru.md) | [Español](README.es.md) | [Português](README.pt.md)

**Tidy Display** — um plugin da comunidade para o DeepSeek Harness (DSH) **0.1.0–0.2.0** que une a vista de leitura e a trilha de mensagens em um só plugin: sessões longas ficam fáceis de percorrer, de navegar e de retomar.

> Este projeto nasce da fusão de dois plugins muito populares do DSH:
> [dsh-better-display](https://github.com/aa2246740/dsh-better-display) (vista de leitura, mantida por meio de um fork) ×
> [dsh-tidychat](https://github.com/BananaSoldier01/dsh-tidychat) (trilha de mensagens / carregamento inteligente do histórico).
> A fusão elimina o conflito de contrato DOM entre os dois; crédito e agradecimentos a ambos.

## Procedência e agradecimentos (declarados tal qual)

**A vista de leitura ao vivo** vem do [dsh-better-display](https://github.com/aa2246740/dsh-better-display): a renderização em streaming do upstream aa2246740, a coreografia de recolhimento do processo e a ponte oficial, aprimoradas pelo fork de drscrewdriver. Este projeto não reescreveu o pipeline de renderização nem o de animações.

**A trilha de mensagens** vem do [dsh-tidychat](https://github.com/BananaSoldier01/dsh-tidychat): a trilha sobre canvas, o hover olho de peixe, a cadeia de cores e o carregamento inteligente do histórico são porteamentos, aprimorados pela linha compat de drscrewdriver (brilho branco, paridade com o steering, o DOM como única fonte de verdade).

### Falhas do better-display original, corrigidas por este projeto / pelo fork

1. **Sem placa atrás das mensagens nem do raciocínio** — as respostas finais e o texto de raciocínio são colocados diretamente sobre o fundo da página; a legibilidade sofre com skins, papéis de parede e temas escuros. → O fork adicionou às respostas a placa translúcida oficial `--dsw-alias-bg-layer-1`, e ao cartão de raciocínio o mesmo fundo (commits `fa3a795`, `94d59c7`).
2. **A vista de leitura perde as âncoras por linha do host** — `data-chat-anchor-key` / `data-chat-flow-kind` não são emitidos junto às linhas de mensagem, então plugins de terceiros que dependem desse contrato como fonte de verdade do DOM (por exemplo, a trilha do tidychat) resolvem zero linhas e **falham em silêncio** na vista de leitura. → A correção foi enviada ao upstream como [aa2246740/dsh-better-display#41](https://github.com/aa2246740/dsh-better-display/pull/41); o projeto fundido inclui a mesma correção.
3. O TimelineRail dele é uma única trilha com o esquema oficial — sem resumos olho de peixe, sem salto por clique, sem cores.

### Falhas do dsh-tidychat original, e o motivo da fusão

1. O recolhimento / os separadores são cirurgia de DOM que se sobrepõe ao recolhimento nativo do host (0.1.2+), obrigando o usuário a escolher manualmente entre um e outro.
2. As versões v0.2.10 e anteriores liam mal a instantânea em hosts DSH 0.1.2 — a trilha resolvia zero rodadas e **nunca chegou a ser renderizada de fato** (corrigido na v0.3.0; veja `docs/RAIL-ROOT-CAUSE-ANALYSIS.md` no repositório dele).
3. Entrava em conflito **nos dois sentidos** com a vista de leitura do better-display: a cirurgia do tidychat não alcançava as linhas da vista de leitura, e as âncoras perdidos pela vista de leitura por sua vez inutilizavam a trilha — a motivação direta desta fusão.

Obrigado aos dois upstreams e aos seus autores (aa2246740, BananaSoldier01) — este projeto está sobre os ombros deles. As melhorias do upstream que não entrarem em conflito serão incorporadas quando for a hora.

## Funcionalidades

### Vista de leitura (do better-display)
- Os passos de execução se recolhem em resumos expansíveis; as respostas finais são apresentadas como **bolhas de mensagem** (placa translúcida + vidro fosco opcional que deixa ver os fundos das skins)
- O cartão de raciocínio compartilha a mesma placa translúcida; o raciocínio em streaming pode acompanhar o deslocamento, pausar e ser totalmente expandido
- Ponte oficial: vistas de ferramentas, feedback, cartões de entregáveis, turnTail e demais são renderizados pelos slots oficiais
- Os blocos `` ```mcp-app `` são montados como cartões interativos isolados (`<iframe sandbox="allow-scripts allow-forms">`); pacote de skills em [`skills/generative-mcpapps/`](skills/generative-mcpapps/)
- Linha de entregáveis, relógio de espera, eco de pendentes; a «Conversa / Trajetória» original, a caixa de entrada, o seletor de modelo, as ferramentas e as aprovações continuam lá

### Trilha de mensagens (do dsh-tidychat)
- Trilha de navegação sobre canvas na borda da conversa: hover olho de peixe com cartões de resumo, salto por clique, destaque da rodada atual ao deslocar
- Estilos **barras / pontos**, posição **borda esquerda / direita (espelhada)**
- **Anel de brilho branco**: um brilho suave sob a marca da rodada atual e da rodada sob o cursor as mantém legíveis sobre fundos movimentados
- **Cores**: a cor das marcas e a cor de destaque oferecem cada uma Automática (segue o tema, com correção automática se faltar contraste) / Personalizada (seletor de cor + texto HEX/RGB + controle deslizante de opacidade)
- **Assume o controle da trilha de mensagens oficial**: oculta o TurnNavigator oficial da borda direita (oculto, não desmontado) e deixa somente esta trilha
- Funciona em **ambas** as vistas: a vista «Conversa» nativa e a vista de leitura

### Configurações
Todas as configurações ficam em **Configurações → 起子插件设置 → 整洁显示 (Tidy Display)**: trilha de mensagens (interruptor / posição / estilo / brilho / tomada de controle / cores) + bolhas de mensagem / vidro fosco translúcido / recolhimento automático / modo de abertura de entregáveis. A configuração persiste em `dsh.reader.v1`.

## Instalação

> ⚠️ **Excludente em relação a `dsh-better-display` e `@bananasoldier01/dsh-tidychat`**: os três registram uma vista `reader` (mesmo id, mesma prioridade) no slot de lista `conversation.view`. Ativá-los ao mesmo tempo faz a ativação falhar por registro duplicado (o cliente informa `entry did not activate` e a página fica presa na tela de falha de carregamento de plugins). Desinstale ou desative aqueles antes de ativar este plugin.

### App de desktop DSH Studio (recomendado)

Abra **Configurações → Plugins → Adicionar plugin** e digite o nome do pacote:

```text
dsh-tidy-display
```

### Web CLI

Publicado no npm — instale pelo nome simples:

```sh
dsh plugin --profile web add dsh-tidy-display
```

O endereço do GitHub também funciona (as linhas compat de hosts antigos se instalam por tag; veja a matriz acima):

```sh
dsh plugin --profile web add github:drscrewdriver/dsh-tidy-display
```

Diretório local / tarball (desenvolvimento / teste local):

```sh
dsh plugin --profile web add ./dsh-tidy-display
dsh plugin --profile web add ./dsh-tidy-display-0.1.0.tgz
```

`dsh.bundle` é capturado na inicialização: **não** escreva manualmente a mesma linha de insert no `cordis.patch.yml` do perfil (montagem dupla); para remover uma cópia já instalada use `dsh plugin --profile web remove dsh-tidy-display`. Para um Web Host já em execução, reabra o Host uma vez e recarregue a página.
